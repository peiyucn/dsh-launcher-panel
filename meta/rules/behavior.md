# 行为规范

> 规范层。被 `AGENTS.md`、`playbooks/`、`skills/` 引用；不反向依赖它们。
> 来源：原 `AGENTS.md` 的 A、B2、C、D、H、I 段；保留原章节号只作导航，不是新编号体系。
> 项目清单不在本文件，见 [PROJECTS.md](../PROJECTS.md)。

## A 仓库约定

### A1｜本仓库只管根目录〔final〕

跟踪根目录的说明与配置文件，以及 `assets/` 下的品牌源文件。各子项目统一放在 `projects/`，内容由 `.gitignore` 整体忽略，各自有独立仓库。

### A2｜临时文件放 `TEMP/`〔final〕

过程产物一律放这里。该目录内容全部忽略，只跟踪 `.gitkeep`，clone 下来目录即存在。

### A3｜文件名用英文〔final〕

本仓库与各软件项目仓库的文件夹、文件名用英文。内容与笔记类仓库豁免。

## B 目录命名

项目清单是事实，已移到 [PROJECTS.md](../PROJECTS.md)；本文件只保留 B2 目录命名规则。

### B2｜目录命名规则〔final〕

| 目录 | 含义 |
|---|---|
| 无前缀 | 活跃项目 |
| `projects/_archive` | 已归档，不维护，不在恢复范围（整目录忽略）。含 `agent-plugins-updater`、`JPwd`、`JSParse` |
| `TEMP` | 临时文件区，不是项目 |

## C 工作约定

本段约束 agent 的工作方式，不涉及代码本身。模型在「完成任务」的压力下容易编造、猜测、跳过验证、掩盖失败。

### C1｜用中文表述〔final〕

与 owner 交流、编写 commit 描述一律用中文，commit 保留英文类型前缀。代码注释以英文为主，写明「为什么」而非复述代码。

### C2｜未知须明示，禁止编造〔final〕

未查到的须标明「未查到」，未验证的须标明「未验证」。禁止编造任何具体信息，不得以确定语气描述未执行的操作。

### C3｜结论须有依据〔final〕

关于当前状态的判断必须取自命令输出或文件内容。推断只能用于提出假设。

### C4｜不用取巧写法〔final〕

禁止用取巧手法让代码跑通。找不到正当解法时停下来说明，不硬过。

### C5｜不隐瞒错误与异常〔final〕

禁止为通过检查而造假，禁止隐瞒缺陷或验证失败。无法修复时如实说明，发现此前结论有误时主动更正。

### C6｜如实说明当前状态〔final〕

进展须区分已实现、已提交、已推送、已发布、已上线验证五级。不得用「完成」笼统概括。

「已上线验证」指 owner 已确认线上正常，agent 无法自行判定。

### C7｜不可逆操作须先经 owner 同意〔final〕

判断标准：执行后能否无损回滚。不能的即为不可逆操作。无法判定时按不可逆处理。

可逆操作直接执行，无需报批。

### C8｜完成后须自检〔final〕

挪动代码后确认旧位置真的没了；说「完成」前逐项核对哪些真做了、哪些没做。

### C9｜修改 AGENTS 须经 owner 许可〔final〕

适用范围：本文件与各项目的 `AGENTS.md`。未经 owner 要求或明确许可，不得修改。

发现需要调整时先提建议，等答复后动手，不擅自扩大范围。

规范须具备约束力：被约束方能随时改动它，约束即不存在。

### C10｜新功能完成后先讨论重构方案〔final〕

功能跑通只是可用，不等于完成。新功能可用后立刻整理一轮重构方案（收敛实现、去重、删死代码、重写命名与注释），**先与 owner 讨论、确认后再执行**；重构行为保持不变，`verify` 保持全绿，且与功能分开提交。未重构的新功能不算完成。

## D 工具

### D1｜浏览器操作〔final〕

查看自有 GUI、登录态、多步交互、截图，须先在 profile 中挂载 browser use，方可使用浏览器工具。默认未挂载，引擎用本机 Edge。

禁止下载浏览器，本机 Edge 已可用。例外仅限导出 PDF 的脚本自行安装 playwright 依赖。

浏览器产物目录落在调用时的工作目录，已配置全局忽略，无需逐仓库添加。

### D2｜GitHub 操作统一使用 `gh` CLI〔final〕

GitLab 仓库用 `git` 或 `glab`。

### D3｜代理配置〔final〕

git 与 agent 宿主进程均不读取系统代理。需要走代理时须显式指定：git 用一次性参数，宿主进程设环境变量并开启环境代理支持。不写入配置文件。

## H 文档规范

以下规则针对该项目实际存在的文档；不存在的文档不适用。

### H1｜AGENTS.md〔final〕

中文一份。面向开发 agent，只写规则、契约与做法。

### H2｜README〔final〕

中英双份，英文为默认，顶部互链。面向用户，写安装、使用、配置方式。有已知限制或安全隐患时一并写明。

### H3｜CHANGELOG〔final〕

中英双份，英文为默认，顶部互链。面向用户，每条一项可感知变化。

格式遵循 Keep a Changelog：标题 `## [x.y.z] - YYYY-MM-DD`，从新到旧；日期取发版当日。依赖不进入产物时写明「无用户可感知的变化」。

## I 项目 AGENTS 结构

项目 AGENTS 只写项目事实、项目值/接口、override、项目专属规则和本地 meta 引用；共享规则不复制。

### I1｜只允许的区块〔final〕

| 区块 | 写什么 | 约束 |
|---|---|---|
| 项目事实 | 是什么、源码/文档位置、命令、关键文件 | 只写本项目事实 |
| 项目值 / 接口 | 分支、verify、required checks、发布、tag、环境 | 填项目值 |
| Override | 对 `overridable` 规则的偏离 | 必须写 `override: <规则> → <值/理由>` |
| 项目专属规则 | 架构契约、宿主限制、测试规范、本地判断 | 标 `scope: project`；只能更严或更具体，不能放宽 `final` |
| 本地 meta 引用 | `meta/` 快照来源和路由 | 必须自带快照，不能只链远端 |

`final` 不能覆盖。没有 override 就写“无”，不要复制 meta 的 shared rule 全文。

### I2｜本地 meta 快照〔final〕

各仓库独立运转，单独 clone 时读不到 meta-repo。项目必须带本地 `meta/` 快照，并在 `meta/SOURCE.md` 写清来源提交和适用范围。

项目 AGENTS 通过本地 `meta/` 路由到规则、原则、技能和 playbook；不要把这些内容复制进 AGENTS，也不要只写远端链接。

### I3｜独立运行〔final〕

项目 clone 后应能只靠本仓库运行：`AGENTS.md` 是入口，本地 `meta/` 提供共享规则，`verify` 提供执行检查。

快照里的 A/B/I 段、`PROJECTS.md`、`github-policy.json` 和 meta 自己的脚本属于 meta-repo 工具层；项目 AGENTS 必须声明哪些部分适用、哪些不适用。

### I4｜本文件不写项目实现细节〔final〕

项目专属的架构契约、宿主兼容规则、上游限制、测试规范，写入该项目自己的 AGENTS 或项目文档。

判断标准：写一条规则时若必须知道「是哪个项目」才能理解，则该规则不属于本文件。本文件允许出现项目名的地方仅 PROJECTS.md 的项目清单、项目管线与 B2 的登记。
